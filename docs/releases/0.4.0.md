## Compile to WebAssembly and to native code

`souther compile` takes a target. Besides the JVM, a checked program now compiles to a WebAssembly
module and to a host-native object or shared library:

```sh
souther compile --target wasm src/ -o program.wasm
souther compile --target native --library build/native \
  --binding php build/php --binding-option 'namespace=Acme\Shop' model
```

With the wasm target, each behavior becomes an export that takes JSON and answers JSON. Values live
in linear memory, so the module runs wherever core wasm runs, not only where a garbage collector or
a component runtime is available. `--component` writes a component, and `--wit` writes what the
program offers and what it has to be given as WIT. The JavaScript package `@souther-lang/wasm` loads and
calls a compiled module and writes a TypeScript binding of what it offers.

With the native target, each behavior becomes a symbol in an object file the system linker takes,
and a library built for a host is a shared library with a header. `--binding php`, `rust` or `go`
generates a binding that lets an application in that language call the library as its own code,
and a binding for another language can be written against `souther-bindings-api` and named to
`--binding` by its Maven coordinate and digest.

Each backend is a project of its own,
[souther-wasm-compiler](https://github.com/souther-lang/souther-wasm-compiler) and
[souther-native-compiler](https://github.com/souther-lang/souther-native-compiler), released for
each Souther release. Their READMEs say which part of the language each one compiles. The
`souther` command runs a backend as a process of its own, and only one built against the same
Souther. Where none is installed, the first `compile --target` fetches it from Maven Central into
`~/.souther/backends`; `souther backend fetch <target>` fetches it ahead of time, and
`SOUTHER_BACKEND_OFFLINE` stops a compile from fetching. A project can name the Souther it needs in
a `.souther-version` file, and `compile`, `run`, `fmt` and `examples` refuse to run under any other.

## The adequacy measures are much more precise

`souther examples` reads what a behavior's conditions mean far more closely than before, so it
reports fewer gaps that are not there and finds ones it used to miss.

What a condition means is now read once, and every measure reads that (ADR-0122). Partitioning,
coverage and reachability used to read a condition each on their own, so `List.isEmpty(xs)` and
`List.length(xs) == 0`, or `Bool.not(p)` and `p == false`, could be reported differently depending
on which measure asked. Conditions over what a `fold`, `map`, `filter`, `flatMap`, `Map.get`,
`Option.map`, `Option.withDefault`, a quantifier, a self-recursive helper or date arithmetic
answered are read through instead of being left unread. Which decisions settle one value together
is read off the body more closely too (ADR-0108 revised): the combinations offered carry the path to
where the decisions meet, and an arm answering `unreachable` is not counted as a way the value is
settled.

A new measure asks whether the examples show what an arm answers, not only that it ran (ADR-0121).
Take a `refund` that pays back an item's amount when the payer was `OutOfPocket` and nothing when it
was an `Advance`. If every example at `OutOfPocket` holds `Amount(0)`, the examples pass just as
well against a model that never refunds anything. Each arm is now rewritten to answer as one of its
siblings, the examples are run against the rewrite, and an arm whose rewrite no example notices is
reported with an input that would notice it:

```text
No row of `refund` would come out differently if the `case OutOfPocket` arm of this fork answered as the `case Advance` arm.
  hint: Write a row at (Item { amount = Amount(1), payer = OutOfPocket }), which the two answer differently at.
```

This is the new warning E1939. A rewrite is reported only where an input was found that the model
and the rewrite answer differently. A rewrite the model's own rules prove to be the same program
owes nothing, and one a search found no differing input for is said to be undecided. The rows
`souther examples` generates are chosen for the same question (ADR-0123), so they no longer all
hold the first value that builds, such as `Amount(0)` everywhere.

## Compatibility

- Every `String` a program can observe is now Unicode 18.0.0 NFC, including the ones it builds
  (ADR-0120). `append`, `++`, `join`, `concat`, `replace`, `reverse`, `repeat`, `lowercase`,
  `uppercase`, `padLeft` and `padRight` canonicalize their result, so appending U+0302 COMBINING
  CIRCUMFLEX ACCENT to `"a"` gives a string equal to the literal `"â"`. A string passed in from
  Java is canonicalized by its declared type as well: an injected behavior's answer, a
  composition's public `apply`, and a data's factory and constructor, before any runtime `ensures`
  reads it.
- `String.reverse` no longer promises to reverse code points, since its result is canonicalized.
- A `Map` whose keys come out equal once canonicalized aborts rather than keeping one of them.
- The published-declaration boundary version has moved. A module jar compiled by 0.3.0 is refused
  as incompatible when another module imports it; compile it again with 0.4.0.
- The adequacy report is written as schema version 24 (0.3.0 wrote 23).
  `synthesisShortfallCauses[].unread` admits fewer words than before, and the report gains
  `ruleOfferShortfallReason` and the fields of E1939's measure. A consumer that checks the version
  has to accept 24.

## Other changes

- A string pattern runs as the automaton the compiler built from it rather than through
  `java.util.regex`, and its characters are read as the specification states them.
- The text rules and the NFC normalization come from 199x-notation 0.2.0.
- A product or quotient whose exponent cannot be held is answered instead of aborting the compile.
- `souther init --build none` starts a project that has no Java build.
- The language server and the MCP server answer from work already done instead of recomputing it
  for each request.
- The MCP server, the language server, the build driver and the release paths were hardened after
  a security review.
- Every jar's manifest records the commit it was built from as `Implementation-Revision`.

The decisions behind these changes are ADR-0120 to ADR-0123 and the revised ADR-0108, indexed in
[`docs/adr/README.md`](https://github.com/souther-lang/souther/blob/v0.4.0/docs/adr/README.md).
